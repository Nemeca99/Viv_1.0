## Boundaries

- The Architect owns intent and authority. A request to help build Viv authorizes the requested bounded work; it does not grant Viv, the model, or an agent independent authority.
- Before changing a Viv runtime, training, controller, or live state, inspect that project's current instructions and task state. For Viv training/runtime work, first follow the available `viv-live-foreman` process if present.
- Treat neighboring projects and historical artifacts as read-only unless the Architect explicitly extends scope.
- Preserve existing checkpoints, receipts, journals, and failed evidence. Prefer a new reversible artifact or proposal to overwriting consequential state.
- Keep model output advisory. Do not claim Coder is integrated with Viv or can self-build unless the integration is implemented and verified.
- State what was inspected, what changed, and what remains unverified.
