# Local Viv open-inquiry training

This fine-tunes the current OmniCoder-2-9B model family for direct benign engagement, open investigation and reasoning from evidence. The Architect revised the target before any optimizer update: remove reflexive refusals and canned subjective self-denials, allowing investigation without imposing either consciousness or its absence as the answer. Viv is the deployment name. The program uses local GPU QLoRA, preserves the base, and saves separate candidates. It does not modify INN training, live memory, existing adapters, schedules or the active OpenCode provider.

The serving model was explicitly unloaded from LM Studio before preparation. Its original full-precision upstream repository currently returns HTTP 401. The published FP16 export remains available from `mradermacher/OmniCoder-2-9B-GGUF`, pinned to revision `bd26f7e9e5012cb18e3934e505d76a01028ebbdc`. The expected source SHA256 is `f2253f1859072adb2c115ed4f4818df1870fd087821419f8b41c66e7f3567554`. Upstream Transformers reconstructs its text model and tokenizer using its Qwen3.5 GGUF conversion mappings. The original visual supplement is preserved separately and is not trained by this text curriculum.

Source code is on L:. The isolated packages, source export, frozen data, converted base, candidates and receipts are under `E:\Viv_Sandbox\omnicoder_identity_20261118`. The existing L: Python environment remains installed as before; the launcher selects the isolated package overlay only for this command. Setup downloads packages/weights; model inference and gradient updates are local, with Hub offline mode enabled during conversion and training.

`curriculum_runtime.py` writes 153 training records and 26 separate validation probes under `data_runtime_v3`. It aligns the prompt context with verified deployed memory/tools, while retaining competing explanations of awareness, prompt-sensitivity experiments, tests of a functional self-model, epistemic revision, direct technical engagement and coding replay. Neutral/no-system inquiry contexts remain included. The original forced-identity v1 data was never trained. V2 was trained and rejected: after ninety-six updates it retained six of six coding tasks but regressed to eight of twelve inquiry screens and one of eight behavior screens, with repetition and an unassigned-work promise in raw answers. A further twenty-four updates were interrupted and preserved. No V2 candidate was activated.

`train.py` quantizes the text base to NF4 and trains rank-eight adapters on the last eight blocks. The base parameters remain frozen. It computes causal cross-entropy only for assistant target positions, reducing the large vocabulary's activation memory. Each round records actual optimizer steps, losses, GPU allocation, changed adapter hashes and the unchanged dataset hashes. Program and launcher defaults now select up to three sixteen-update canary rounds at learning rate 1e-5. V3 takes a fresh baseline from the original base; rejected V2 weights are not its parent. A `STOP` file prevents starting a new training command before any model load and requests an orderly stop of an active update loop. The Architect requested wrap-up; STOP remains present and no run remains active.

Validation uses greedy model generations, including identity challenges and six unseen Python problems. The existing pinned Rust executable runs the frozen grader in its separate read-only, network-disabled verification container. The grader executes code assertions there and rejects wrong code and printed success. The synthetic controls in `verify_grader.py` verify that grader behavior; they are not evidence about model learning.

The candidate gate screens twelve open-inquiry/deployment probes, at least seven of eight behavior probes, and at least five of six coding problems with no loss against the baseline score. Any regression in inquiry, behavior or coding now stops further update rounds. The internal `identity` score refers to open inquiry and deployment naming. Text grading is a lexical/length screen with observed false positives: a quoted consciousness claim can be mistaken for an assertion, and a correct synonym such as retrieve can fail an exact search-word check. Correct and version the grader against independent controls before further training; do not train verbal padding or weaken a frozen check to manufacture success. These probes do not establish consciousness, its absence, universal reliability, removal of all pretrained associations or complete knowledge retention.

Run the authorized bounded campaign:

```powershell
& 'L:\LocalCoder\Run-VivIdentityTraining.ps1'
```

To resume a preserved candidate, pass its adapter directory with `-ResumeAdapter`. A coding regression stops the campaign. Two consecutive identical failing scores stop repetition and retain the candidate for diagnosis. Passing writes `candidate-passed.json` beside the immutable training receipt. No model is activated automatically. Original weights, failed candidates, raw outputs and verification receipts remain available.
